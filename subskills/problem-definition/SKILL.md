# Problem Definition

先读 [主 skill](../../SKILL.md)。本部分形式化定义任务并解释困难，不提前复述方法实现。本章推荐长度为 1.5-2.5 页，硬上限为 3 页。

若贡献章节存在对有代表性的传统研究路线的讨论，则将章节名改为 Problem Definition and Analysis，并分小节，在问题形式化小节之后，每个子小节形式化讨论一种有代表性的传统研究路线；否则不分小节。

**公式（1）必须是整个问题形式化定义的总核心公式。**

## 目标与输入

起草时可按 [模板指南](references/template-guide.md) 使用 LaTeX 结构骨架，并按实际研究内容调整。

本章应在已有 contributions 的前提下，在 Results and Discussions 后，与 methodology 协同撰写。

## 逻辑结构

研究对象与基本形式化表示 -> 已知信息和待求变量的具体定义 -> 数学目标或决策任务 -> 必要约束与假设 -> 信息或现有范式瓶颈 -> 对方法的设计要求，引出方法论章节。

禁止重复详细讲解与核心 contributions 无关联的基础理论。

## 建模规范

- 区分物理对象、观测、未知量、模型估计值与真实值；区分单样本、批量、训练分布和预测任务。
- 首次使用的符号、集合、索引、维度及必要单位，必须给出明确定义。禁止一切无定义的内部代号。该章节的定义必须做到内部自洽，无明确形式化定义的部分，必须给出足够明确的文字解释。一切定义语句，禁止使用任何否定语气进行范围排除，必须全部从正面描述。
- 问题形式化定义表达，必须明确输入输出、定义域和值域，且数学部分能够独立自洽，关键输入输出与物理场景关联表达明确。
- 明确阐释影响定理、辨识或求解在数学上成立的潜在假设。尽量使用简洁严谨的表述。此处禁用否定语气。
- 使用的约束须与后续实验部分的算法、指标相一致。
- 公式后解释其问题含义和作用，核心输入/已知量放在行间公式上文；公式输出量、中间变量与局部角标放在下文。尽量避免重复冗余定义，严禁对同一符号给出不同定义。
- 禁止出现任何实验条件定义和结果描述，禁止引用或依赖方法论章节的符号。
- 最小定义：所有后文需要出现的符号都要有所定义；且后文未出现的符号，不要单独定义。此处可与方法论章节协同修订。

## 从分析到贡献

若撰写传统路线分析的相关子章节，则按照本节执行，否则跳过。

每项重点分析应回答“该方案的障碍是什么，按照问题形式化小节的框架进行形式化后，暴露了什么问题，需要什么机制”。必须将该项方法嵌入问题定义子章节的形式化框架中，并从数学与工程实际相结合的角度，严谨而明确地阐明该路线的理论缺陷。

必须用肯定式落脚到该路线的理论缺陷与设计需求，禁止使用否定语气对 research gap 做任何反向范围限制。

必须能为主创新点提供 motivation。

## 验收与输出

- 首次使用的符号、集合、索引、维度及必要单位，均给出了必要的明确定义。
- 数学部分必须内部独立自洽。
- 非必要不进行重复冗余定义，不存在任何自相矛盾的定义。
- 基本符合逻辑结构。
- 不包含任何实验条件定义或结果描述，也不引用或依赖方法论章节的符号。
- 定义的所有符号、公式都在后文有所引用，边界干净清晰。
- 公式（1）即整个问题形式化定义的总核心公式。
- 篇幅在硬限制以内。
