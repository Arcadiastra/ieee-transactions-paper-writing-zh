# Citation

先读 [主 skill](../../SKILL.md)。以下为本套件默认显示样式，不代表所有 IEEE 刊物都强制使用；目标刊物明确要求优先。**引用的文献总数必须不少于 30 篇，其中 IEEE Trans. 来源的文献不得低于 20 篇。**

注重引用质量：尽量少引用 JCR Q3 及以下级别期刊论文与层次较低的部分会议论文。多引用 Q1、Q2 的高水平文献，尤其是 IEEE Trans. 来源的文献。建议着重引用近 15 年以内的文献。对于与 AI 交叉的领域，可以适当引用相应顶会文献，但仍应以 IEEE Trans. 来源为主。

禁止引用 ResearchGate 等来源，要追溯到文献的最终来源。且尽量追查到结论的最终来源，避免大面积引用同一篇综述类文献。

## 核查

1. 引用逻辑：该文献在本句中承担背景、方法路线、基线、数据来源还是具体论断的支持？实际内容是否匹配？
2. 出版事实：作者、题名、来源、年份、卷期、页码或文章号、DOI 和版本关系是否正确？
3. 显示格式：已核实的信息是否按全篇一致样式输出？
4. 该引用是否是正式发表来源？若不是，是否存在更加权威的来源？
5. 这篇文章所处的分区如何？这篇文章本身的质量如何？
6. 这篇文章是否是该处结论的最终来源？能否进一步追溯到真正的出处文章？

## 引用写作

起草时可按 [模板指南](references/template-guide.md) 使用 LaTeX 结构骨架，并按实际研究内容调整。

- 引用靠近对应论断，尽量避免把整段不同主张交给段末一串文献承担。
- **同一处连续并列引用不得超过 3 篇文献。** 超过时，应按具体子论断分配引用，或保留最直接、最具代表性的文献。同一处相邻的多个引用命令合并计数，编号范围按实际包含的文献篇数计数。
- 相关工作按方法思想归类，并说明与当前问题的关系；避免按年份流水账或数量堆积。
- 优先直接支持论断的原始研究；综述用于概括领域，具体方法的引用尽量追溯到原始来源论文。
- 引用已有组件和最接近工作，清楚区分继承与创新。

## 默认显示规范

| 项目     | 规则                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 作者     | 名字缩写在姓前；六人及以内全列，超过六人首作者加 et al.；数据库保留完整作者      |
| 重复作者 | 每条明确列出，不用横线替代                                                       |
| 题名     | 句首大写，保护缩写、专名和模型名称的准确大小写                                   |
| 刊名     | 使用一致的标准缩写，例如 IEEE Trans. Signal Process.                             |
| 日期     | 经核实的卷、期、页码或文章号、正式出版月份和年份；不混用 online-first 与卷期日期 |
| 连续出版 | 没有期号或月份时不补造                                                           |
| 页码     | pp. 起止页；文章号采用 Art. no.，不能误作单页页码；不无意义重复两套标识          |
| 会议     | in Proc. 加规范会议名；卷页只写官方记录支持的内容                                |
| 预印本   | 作者、题名、年份和 arXiv 编号等真实标识，不伪装成正式发表                        |
| DOI/URL  | 普通期刊和会议条目默认不显示，库中保留已核实字段；网页、数据等按类型保留必要地址 |
| 文内编号 | 按首次引用顺序，用 [1], [2], [3] 等独立方括号，不压缩成编号范围                  |

## IEEEtran 实现参考

沿用已有 BST 和控制条目，不手工修改生成的 bbl。检查已有包设置再使用：

```latex
\usepackage[nocompress]{cite}
```

在有效的 BST 控制条目中设置，沿用相应调用方式：

```bibtex
CTLuse_url = {no},
CTLuse_forced_etal = {yes},
CTLmax_names_forced_etal = {6},
CTLnames_show_etal = {1},
CTLdash_repeated_names = {no}
```

不同 BST 的支持情况不同，以编译结果为准；不把这些字段直接粘进普通文献条目。

## 核验流程

- 只处理授权范围内实际引用条目，不顺手重写储备文献库。
- 优先论文首页、出版方记录和官方 proceedings；Crossref 与作者页面用于交叉验证。出现冲突时说明依据，不凭姓名习惯猜缩写。
- 查正式版时核对作者、题名和内容关系。Workshop 与主会、预印本与期刊、改题名的不同版本必须区分。
- 未核实的字段保持待确认，不补造 DOI、月份、卷期或页码。原始数据保留准确元信息，显示规则单独处理。
- 改后编译核对编号、作者截断、刊名、大小写、文章号、链接和未定义引用，并查看参考文献页面。

## 交付

### 脚本与原文核查

- 开始批量核验前，读取 [工具说明](references/tools.md)，先运行只读的离线 BibTeX/AUX 检查。联网核验必须显式开启。
- 用户明确要求联网核验时，出版元数据优先使用已安装且版本兼容的 Bibverify 官方 CLI，按 [CLI 接入说明](references/bibverify-integration.md) 使用 `--dry-run --json`；禁止 `--apply`，不自动安装或升级。未安装或版本不兼容时使用 `scripts/verify_metadata.py`，说明实际后端。
- Bibverify 会核验整个输入 `.bib`，没有 `--aux` 过滤参数；仅核查已引用条目时先确认引用子集。撤稿、更正及关注声明通知仍使用 `scripts/check_updates.py`。网络失败、未被索引、元数据差异与原文不支持论断是不同结论，分别报告。
- DOI 命中只证明返回了对应记录；查看比较字段、差异和未检查字段，不把内置脚本的 `MATCHED_FIELDS` 或 Bibverify 的 `verified` 写成“全部核验通过”。即使退出码为 0，也检查 `field_diffs` 中的补充或修订建议。
- 对重点论断按 [引用支持关系流程](references/integrity-review.md) 阅读原文、记录证据位置。
- 公开工具选型与可吸收部分见 [来源比较](references/source-comparison.md)。采用其有用的核验思路。

小修交付实际修改与简要结果；审计可用“条目、问题、来源、处理、核验状态”表。无需在普通改格式任务中自动扩展成完整文献综述。篇幅在硬限制以内。
