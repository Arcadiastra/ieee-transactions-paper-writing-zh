# Methodology

先读 [主 skill](../../SKILL.md)，并读取问题定义和已确认的实现或推导。本部分重点是方法依据与机制创新。本章推荐长度为 2.5-3.5 页，硬上限为 4.5 页。

**采用总-分结构，先总写，后分子章节严谨细致地拆解各模块架构，侧重原创或创新的设计或发现。**

**总写部分包含本章节的第一个公式，该公式必须为本文核心 contribution 对应的模型总公式，且相关符号的含义必须在问题定义章或紧接本公式的段落中有明确阐释。**

## 目标与输入

起草时可按 [模板指南](references/template-guide.md) 使用 LaTeX 结构骨架，并按实际研究内容调整。

本章应在已有 contributions 的前提下，在 Results and Discussions 后，与 problem definition 协同撰写。

## 逻辑结构

先用总体框架公式交代本文方法论的输入、主要处理路径、信息交互和目标输出，再分子章节介绍各核心、创新机制，最后给必要的决策、训练或求解说明。

每个机制按“前置符号与潜在假设说明 -> 机制形式化 -> 创新性、有效性理论分析”展开。标准组件简述其在本方法中的角色；原创机制给足解释空间。此章节的创新性、有效性分析，必须完全从形式化或定性的理论角度展开，如机制层面的合理分析、形式化证明等。

## 表达规范

- 从问题需求和创新机制解释设计，侧重与强调理论创新，避免“用了先进模块所以有效”之类的笼统论证。
- 除摘要与 contributions 的相应部分外，严禁提前泄露任何实验结果或结论，严禁在本章及其之前的任何地方撰写数据集、参数设置等与实验设计工程细节相关的内容。
- 明确哪些是已有组件、哪些是本文的组织或机制创新。对于已有方法或工程实现，必要的部分简洁列举，不关键的部分大幅省略概括。
- 公式、文本、图中符号和维度一致，输入与输出能衔接，完成第二章形式化问题要求的全流程闭环。必要时检查索引、归一化范围、有效元素和约束。
- 为理解机制必需的求解步骤应交代。
- 数据量、全部超参数、硬件、复杂度和调参过程若不属于创新性贡献，不在本章描述。若 contributions 不包括效率或复杂度优势，无需在本章内体现。
- 本章节必须全部都为正面描述，严禁使用任何否定语气。

## 方法图

- 核心目的是介绍模型完整结构，或进行数据流、工作流、控制流等任务全流程的可视化。
- 符合相应领域的科研制图规范。
- 服务于整体结构说明或一个明确论点，并保持抽象层次一致。
- 模块、箭头、符号、连接关系均来自实际研究内容。
- 总体图突出模块协同关系，必要的细节图突出创新机制；尽量避免各图出现冗余重复内容的描述。若总体图较为复杂，视篇幅允许使用跨栏大图。
- 字体和线条在实际栏宽下可读，标签不遮挡箭头；尽量减少空白、重复图例和装饰。
- 避免进行大量工程细节的描述：突出强调有学术创新价值的部分，建议大幅简化或省略实验参数以及常规参数、模块与约束等工程实现细节的描述。
- **严禁在图表中添加任何形式的灰体小号字的解释说明短语或句子。**

## 验收与交付

- 结构与行文基本符合本 skill 的逻辑结构要求，且符合表达规范。
- 总写部分的首个公式为本文核心 contribution 对应的模型总公式，且表意明确。
- contributions 中提到的相关机制，均在本章节被充分形式化与论证阐明。
- 方法图的绘制符合规范，且无 AI 生成或伪造痕迹。
- 对工程细节进行了适当的简化以免喧宾夺主：压缩篇幅时，优先压缩相关非学术创新贡献的工程细节描述。
- 篇幅在硬限制以内。
